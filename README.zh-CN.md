# DeepSeek 翻译插件

[English](README.md) | [简体中文](README.zh-CN.md)

为 DeepSeek Harness（DSH）提供独立的翻译工作区，让翻译、讨论和长期资料积累各有位置。

在故事、游戏剧本或学术材料的翻译中，逐段复制原文、反复解释背景、整理多个译本和维护术语往往比翻译本身更繁琐。本项目将这些工作集中到同一个主题中：主聊天用于讨论和提出要求，翻译工作区用于提交原稿与查看结果，记忆资产用于积累可复用的术语和背景资料。

## 为什么使用它

- **翻译与讨论分开**：待译材料和译文留在翻译工作区，主聊天保留讨论、解释和修改要求。
- **同一主题持续积累**：多个翻译会话共享术语、人物、事实和关系，减少重复说明背景的工作。
- **译文可以比较和修订**：保留不同版本，支持重译、人工修改和最终版本选择。
- **记忆资产可见、可控**：可以查看依据、编辑条目、处理冲突，以及决定是否采纳文件翻译产生的建议。
- **沿用 DSH 的模型配置**：无需在插件里另配模型服务，可为翻译选择模型与推理等级。

## 目前能做什么

| 能力 | 当前范围 |
| --- | --- |
| 快译 | 直接翻译纯文本，适合独立短句、临时查译。 |
| 普通翻译 | 由主模型整理要求与背景，再交给翻译模型处理，支持讨论、重译和纠错。 |
| 文件翻译 | 处理 UTF-8 TXT 原稿；准备术语与背景、分批翻译并交由主模型验收，展示文件结果与资产提案。 |
| 主题与会话 | 新建主题及子会话、备注、排序、归档，并在同一本地资料库内跨主聊天复用主题。 |
| 记忆资产 | 查阅和编辑术语、实体、事实、关系；关联来源，整理参考资料，审阅文件提案。 |
| 版本与导出 | 查看原文与译文、保留旧版本、选择最终译文，按会话或主题导出译文 TXT 和对照 JSON。 |
| 本地保存与清理 | 可选保存历史与主题资产，查看存储占用，按不同范围删除或清理。 |

项目仍处于开发阶段，尤其是普通文件翻译的耗时和交互仍在优化中，不承诺固定完成时间。

当前待译文件仅支持 UTF-8 TXT，单份不超过 2 MiB；不支持直接翻译 PDF、Word 或图片，也不生成 PDF。参考资料能否读取，取决于 DSH 和主模型的能力。记忆资产窗口位于 DSH 应用内，可浮动或停靠，不是独立的 Windows 原生窗口。

## 环境与依赖

- 安装支持本地插件的 DSH，并在 DSH 中配置可用模型。本项目当前适配的环境以 DSH `0.2.0-rc.2` 为基础，不保证其他版本直接兼容。
- **快译**不要求安装 Composer 扩展。
- **普通模式**需要匹配的 `dsh-composer-extension`（当前为 `0.3.0`）及配套 DSH 构建。仅安装扩展仍不足以让官方原版 `0.2.0-rc.2` 支持普通模式的材料联动发送。
- **文件翻译**还要求 DSH 能运行一次性子代理；缺少能力时会显示不可用原因。
- 从源码构建需要 Node.js 22 或更高版本、pnpm，以及并排放置的 `dsh-composer-extension` 源码目录。

插件使用 DSH 已配置的模型服务；模型调用仍可能产生费用。本地保存不代表离线翻译。

## 安装与更新

### 安装

1. 准备插件源码及上述依赖，先按 Composer 扩展的说明完成其构建，再在本插件目录执行：

   ```powershell
   pnpm install --frozen-lockfile
   pnpm build
   ```

2. 在 DSH 插件管理器中，将本目录作为名为 `dsh-translation-plugin` 的本地插件安装并启用。使用普通模式时，也须安装并启用配套 Composer 扩展。
3. 重启 DSH，在主聊天的右侧栏打开“翻译”。普通模式提示依赖不足时，先核对配套扩展与 DSH 构建。

### 更新

1. 先保存需要保留的历史，并导出重要译文和记忆资产。
2. 更新同一目录的源码，重新执行上面的安装依赖和构建命令。
3. 在插件管理器中刷新或重新加载本地插件，再重启 DSH。若没有刷新入口，可卸载后重新安装该目录。

更新时保持翻译插件、Composer 扩展与配套 DSH 构建相互匹配。新版保存的数据可能无法由旧版读取，不要让新旧版本同时使用同一份数据。导出文件用于查阅与交付，当前不能导入恢复，不能替代完整的数据备份。

卸载或禁用插件不会自动清除已保存的本地资料。启动异常时，可使用 DSH 的恢复选项禁用第三方插件，再核对安装版本。

版本变化见 [CHANGELOG](CHANGELOG.md)。

## 使用说明

### 1. 建立主题与翻译会话

首次打开工作区，选择**新建主题及首会话**，或使用**选择已有主题**。主题用于归集同一故事、项目或研究方向的记忆资产；翻译会话用于分开处理具体材料。

- 标题下拉中的 **+** 创建新主题及首会话。
- 右键会话，选择**新建子会话**，在原主题下继续工作。序号递增，不回填删除后的空号。
- **重命名**修改主题名称，影响同主题会话；**备注**只修改当前会话的显示名称。
- 长按会话行后拖动，可调整列表顺序。
- **关闭**只从当前主聊天的打开列表移除；**归档**保留资料，移入侧栏的归档组；**删除**会移除会话内容，需要确认。

模型选择位于输入框右下角，目标语言与模式位于顶部。会话可以从快译升为普通，不能降回快译；需要快译时另建会话。

### 2. 快译：直接取得译文

1. 选择快译模式、目标语言和翻译模型。
2. 在翻译输入框填写待译文本并发送。
3. 在原文下方查看译文，需要时重译或编辑。

快译不读取主聊天上下文、主题记忆或参考资料，也不接收文件。适合不需要持续背景的一次性翻译；有术语一致性或情节背景要求时，使用普通模式。

### 3. 普通翻译：结合要求与背景处理

**翻译输入框放原文，主聊天输入框放要求和讨论。**

- **连同要求发送**：先在翻译工作区放入文本或选择 TXT，再在主聊天中写明本次要求并发送。材料随这次主聊天消息提交，由主模型结合意图和要求安排处理。
- **直接发送材料**：在翻译工作区点击发送。短文本交由主模型处理；文件先在后台准备与翻译，再在需要时交给主模型处理关键语境和验收。

直接发送文件不会自动带入主聊天中另行输入的临时要求。有本次特别要求时，优先使用连同主聊天发送的方式。材料发出后再补充要求，不等于后台任务已经采用；应在主聊天中明确要求调整或重新翻译。

连同主聊天发送文件时，主模型须将本次要求和纠正明确交给后台任务，文字确认不能代替传递。准备或审阅子任务未提交可用的结构化结果时，会明确报告失败并保留已有材料，不自动继续或重试。

文件发送后，工作区显示原稿文件与处理状态，点击文件名可打开原稿。产生结果后显示译文文件，可查看详情、旧版本和资产提案，通过验收的结果可设为最终。较长的普通文本会自动按文件方式处理，无需手动拆成多条短文本。

需要修正已完成文件时，在主聊天说明对应文件和修改要求。主模型可查找已保存任务、读取准确译文，再按原片段进行字面匹配，保存新版本；插件重载后也可处理完整保存的文件结果，无须复用旧提交或重新翻译。位置修订必须同时核对原片段；匹配不唯一、内容不符、版本变化或保存失败时不报告修订成功。

文件的“参考”提供准确文件信息及分页原文读取权限，可随时取消；它不发出翻译命令。重载后需要重新选择参考。明确要求重译或点击“重译”时，先由主模型整理本次要求，再从已保存原稿恢复新任务；旧版文档也使用同一文件流程，保留已有完整译文版本和定稿选择。重译意图发出与任务实际受理分别显示，无须复制内部材料通知。后续任务会保存整理后的主聊天要求；旧记录未保存的临时要求仍需从原聊天核对。

文件任务按输入开销估计安排分区。缺少模型容量或默认输出参数不会单独阻断任务，估算值也不作为模型超限的判定依据；实际调用由宿主和提供商校验。实际超限或结果不完整时保留已取得的原稿与结果并报告错误，不自动重复调用。

已经发送的材料与新的输入草稿分开。继续编辑输入框不会改写已发出的原稿；需要更正已发送内容时，在主聊天中明确指出对应材料与修改要求。

失败时按记录提供的**重新发送**、**移除**或状态查询入口处理。结果未知不代表失败，也不代表可以安全重发，应先核对。重启不会自动续跑模型请求。

### 4. 记忆资产：维护主题的共同资料

从标题下拉最上方的**记忆资产**，或会话右键的**记忆**进入。窗口内可搜索和切换主题；切换查阅主题不会切换翻译工作区的当前会话。

**结构化档案**包括：

- **术语**：原词、译法和可选说明。常见词不必写说明；原创概念或特殊用法可补充必要背景。
- **实体**：人物、地点、组织等，以及别名与描述。
- **事实**：需要保持一致的信息，可关联实体。
- **关系**：实体之间的联系。

可以新增、编辑、采用、停用或删除条目，并查看来源依据。用户明确指定的固定译法不会被模型建议自动覆盖；存在冲突或依据变化的条目需要复核。同主题会话共享这些资产，不同主题独立管理。

文件翻译遵循：**用户指令 = 用户编辑确定的条目 > 用户审阅通过的条目 > 待审阅条目 = LLM 理解的翻译**。用户指令与用户编辑条目冲突时，请求用户指示；待审条目与 LLM 理解冲突时，主模型可自行处理。主模型自行整理的要求不因此成为用户指令。

**文件提案**展示文件翻译整理出的候选资产。可滚动浏览卡片、修改内容、查看依据、单条或批量采纳、不采用，或提交合并意见。“全选待审”会选中该文件批次各页符合当前类型筛选的全部待审卡片，再点“取消全选”可清空选择。采纳后写入主题资料；未采纳不阻碍译文交付。编辑后采纳的条目与用户指令同级，未编辑直接采纳的条目高于模型建议；资产仍保留原来的事实来源归属。

同主题的重复提案会显示为“更新既有条目”，可展开原条目对照；采纳后保留原 ID 并增加版本号。术语按原词及别名、实体按名称及别名匹配；事实还需相关实体一致，关系还需主体、客体和关系名称一致。匹配不唯一或原条目已停用时保留待审，不自动合并。采纳用户固定条目的新版本后，仍保留用户固定属性；审阅期间原条目发生变化时须重新核对再采纳。

提案说明使用 DSH 当前语言，原词、必要别名和引文保留原文。人物等名称优先归为实体，所需名称译法可保留在本次翻译基线中，不重复生成术语档案。历史已采纳内容不会自动迁移或翻译。

文件提案默认打开最新可审批次，可切换旧文件，并按全部、术语、实体、关系或事实筛选。待审项排在前面，已采纳项移至底部；全选和批量操作只作用于当前类型筛选中的待审项，范围包括各页。

**译文记录**逐条并排展示原文与译文，可选择某个会话或整个主题；窄窗口上下排列。图片、表格、代码等原件可通过可点击占位链接关联并打开；这不代表会自动解析或翻译其中内容。公式有可用公式源时可尝试预览。

需要外部参考时，在主聊天附上资料并说明目标主题及用途，让主模型整理为主题资产。PDF、表格、图片等参考资料是否能读懂，由主模型能力决定。当前没有开放独立的“其他记忆”和“临时文件”管理页面。

### 5. 修订、定稿与导出

- **重译**追加新译文，保留旧版本；模型选择变化不会改写已有结果。
- 短文本可通过**编辑**追加人工版本，不覆盖原文。需要主模型讨论某条已有记录时，点击**参考**，再到主聊天提出要求。
- 文件行不提供直接编辑；需要修改时在主聊天说明并重新处理。打开文件后在外部修改，不会自动写回插件。
- **设为最终**固定要保留的译文。短文本也会在后续材料受理或导出时，按完整性规则自动定稿；用户手动固定的选择不会被自动替换。文件结果须先通过验收才能定稿。
- 右键会话选择**导出译文 TXT**或**导出对照 JSON**，再选择当前会话或整个主题。记忆资产的译文记录页也提供导出。
- 导出使用最终译文；缺项时会提示，可明确选择导出部分结果。主题档案另有 JSON 和 Markdown 导出，不包含在译文文件中。

导出内容不是完整项目备份；对照 JSON 和档案快照目前不提供导入。下载提示表示已发起下载，请自行确认文件保存位置。

### 6. 保存、存储与清理

在 **DSH 设置 → 翻译** 配置新会话默认的模式、目标语言、翻译要求和单次上限。有效设置即时保存；**恢复默认设置**不清除已有历史，也不改写已有会话配置。

**允许保存会话历史到本地**默认关闭：

- 开启后保存会话、原文与译文版本、最终选择及主题资产；文件需以界面的保存状态为准。
- 关闭后保留已有保存副本，停止后续内容保存；未保存内容在重启后可能丢失。
- 模型与推理等级偏好独立保存，不受此开关控制。
- 资料以明文保存在本机。此开关不控制 DSH 自己的主聊天记录、模型请求记录或附件保存。

在设置的**存储与空间**查看占用，或手动**回收未引用原稿**。不同清理入口的范围不同：

| 操作 | 作用 |
| --- | --- |
| 删除会话或单元 | 清除所选内容；会话删除默认保留主题记忆，联动选项以确认页为准。 |
| 清空本主题记忆 | 在记忆资产中清空所选术语或结构化档案，保留会话与译文。 |
| 删除主题 | 清除该主题及其会话、主题资产和关联资料，以确认页为准。 |
| 清除本地数据 | 清理本插件的本地资料与设置，不删除用户原文件或 DSH 主聊天历史。 |

运行中或结果未知的任务应先结束或核对，再执行相关删除。已导出的文件、已发送给主模型的内容不会随本地删除撤回。
