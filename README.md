# DeepSeek Translation Plugin

[English](README.md) | [简体中文](README.zh-CN.md)

A lightweight translation session panel for DeepSeek Harness (DSH). Quick mode translates plain text with a model already configured in DSH, retaining each admitted text unit, its revisions and one final-version selection. Local history is off by default; enabling it saves those records with session details and the current source draft.

Topics share terminology, entities, facts and relations through an independent memory-asset view and scoped main-model tools.

## Current features

- A right Sidebar panel with a title dropdown for existing sessions and a collapsible session list, collapsed by default. Each independent session retains its own input and configuration.
- **+** creates a new topic and its first session, initially named “新翻译会话”. Creating from an existing session uses the next sequence in that same topic, such as “故事A-01” and “故事A-02”. Creating from a child does not nest suffixes or fill deleted sequence numbers.
- Rename changes the topic name for all its sessions while keeping IDs and sequence numbers. Each session also has an independent remark, which may be duplicated or cleared. Lists, the sidebar and current title display the remark in place of the generated session name; hover text still shows the original name and remark.
- A left-aligned current title dropdown with context actions and right-aligned mode/language controls, a scrollable conversation area and a simple composer with a circular Send button and no blue focus outline on its text area.
- Creating or switching sessions keeps one mode control and one target-language control in the header, without accumulating inactive copies.
- Service checking, unavailable status and the reason Normal submission is blocked appear immediately above and outside the composer. Quick mode provides a compact check icon at the right of the status line, disabled while checking; the line disappears when the service is ready. A single history-retention note appears in the records area after translation records exist.
- Model selection sits at the composer's lower right, immediately left of Send. It uses DSH's native menus and icons and the same `session.modelCatalog()` directory API as the main composer. Its model/effort menu supports provider groups and search; selection applies only to the current translation session.
- The composer toolbar supports one UTF-8 TXT file in Normal mode (up to 2 MiB); replace or remove it from the composer. Long Normal-mode text is automatically packaged through DSH's native TXT upload as a fixed source reference when it exceeds 8,000 Unicode code points, the session's current single-input limit, or the 196,608-byte inline-material limit. No separate file save or extra confirmation is needed. Quick mode is unchanged. Manually selected TXT and body text still require choosing one; saved document history retains each source version as inline text or a managed source identity, while raw TXT bytes stay outside browser history. Whole-file translation is unavailable.
- Quick mode sends the current plain-text draft, target language and explicit translation requirements through a selected DSH Host model, then displays the source and translated result in the conversation area. Only models and reasoning efforts exposed by the Host catalog are selectable.
- Normal mode prepares plain-text or one TXT file as material for the owning main conversation. Main-Send attachment and direct submission use the optional `dsh-composer-extension` Client adapter when installed, or a host `conversation.submissions` seam explicitly marked protocol v1. An unversioned seam is not used. Official DSH `0.2.0-rc.2` provides neither, so Normal submission remains unavailable there.
- For delivered Normal material, the main model can use `translation_read_source` to read the frozen source in bounded ranges when the main notice carries a fixed reference.
- The main Agent can explicitly start terminology analysis with `translation_analyze_terminology`, check it with `translation_analysis_status`, and page through candidates, coverage and call facts with `translation_analysis_read`. Analysis uses the selected translation-session model and available DSH provider to scan delivered, frozen source ranges in the background. Omitted ranges scan the full fixed source; explicit ranges limit the scan to those positions. Each candidate's semantic content is the exact source term, a suggested translation and an optional note. Only successful, structurally valid analysis of the requested ranges counts toward coverage, and an empty candidate list is valid. Coverage records the source ranges analyzed; it does not certify the semantic quality or completeness of the suggestions. Status and page reads do not start another model call; an unknown outcome must be queried, not automatically restarted. Analysis does not create or consume a translation unit, revision or final version, change the draft, or modify topic terminology. The main Agent route must be able to call its registered tools, and the frozen translation session must have a selected model/provider available through the DSH Host adapter; the analysis model itself does not require tool calling. Optional phase notifications require `dsh-composer-extension` 0.2.0; without it, results remain queryable without an automatic main-Agent notification.
- For delivered material, the main Agent can create a task preparation catalog with `translation_batch_prepare`, set an immutable preparation version with `translation_batch_set_preparation`, check it with `translation_batch_preparation_status`, and read bounded audit pages with `translation_batch_read_preparation`. Exact source-term/translation matches are merged; different translations for the same source term remain conflicts, while homonymous meanings can be scoped to non-overlapping source ranges. The main Agent selects analysis candidates or topic terms by ID and version, organizes requirements and selects source ranges for context without asking the user to approve every candidate. It can adjust a selected candidate's translation or note in a task snapshot; the exact source term and original analysis candidate remain unchanged. User-fixed terminology remains binding, and task selections or revisions never change permanent topic terminology.
- A preparation snapshot records the selected route, keeps the material's original translation requirements and adds the main Agent's organized requirements, scan coverage, reviewed ranges, selected terms, source context and unresolved questions. Source ranges can supply background; external reference registration and authorized reading are not supported. Saved preparation snapshots use an independent schema 1 audit store controlled by local history retention. Analysis results, candidate catalogs and source authorization remain runtime-only. After restart, a saved audit can be read while its owning translation session exists, but it cannot be edited, rescanned or used to plan or execute a document.
- For delivered material with a ready preparation, the main model can use `translation_batch_suggest_plan` for bounded chapter, paragraph, sentence and capacity boundary suggestions, then submit an immutable plan version with `translation_batch_set_plan`; `translation_batch_plan_status` and `translation_batch_read_plan` expose its validation summary and pages. Every source code point must be covered once by an ordered `translate` or `copy` range. A `copy` range marks source text for verbatim retention in a future execution and adds no translation-model call to the budget. Context and preparation background are for understanding only, are marked not to be output, and appear in the prompt as non-output context; only the translated range is returned as output text. Protected ranges must be supplied explicitly; the planner checks translated block boundaries and, for translated blocks that overlap one, includes the exact source span and preserve-exactly instructions in the prompt. Those spans and instructions are included in prompt capacity checks. The planner does not infer protected text. If a protected span cannot fit in one translated block, planning reports the range conflict so the whole span can be marked `copy` or capacity adjusted. Source ranges excluded from analysis are suggested as `copy`.
- Each plan is bound to its fixed source and preparation route, including the actual prepared provider, model and reasoning effort. Planning checks translated output against the session's single-body limit, completed scan and main-model review, relevant terms, the reconstructed prompt and output reservation. Fixed rules are checked against their actual matches in this source; unrelated fixed terms do not block planning. If a relevant fixed rule changes or the source contains a relevant fixed term missing from the preparation, a new preparation version is needed before planning. The single-body limit applies to translated output code points; context is budgeted separately as part of the reconstructed prompt. The source is limited to 2 MiB; each prompt package is limited to 196,608 UTF-8 bytes; a plan has at most 256 chunks and at most 8 combined context/background ranges per chunk. The call budget combines actual terminology-analysis calls, one planned call per translated chunk and up to three reserved supplements, with a task maximum of 512.
- Capacity uses DSH's prepared route and its available context-window and maximum-output limits. Input tokens are estimated as the complete reconstructed prompt's UTF-8 bytes plus 16; output size is estimated from the translated source's UTF-8 bytes. When an actual maximum-output limit is available, the plan reserves that amount and checks the estimate against it; otherwise it reserves the larger of 128 tokens and twice the output-byte estimate. If a context window is available, the input estimate plus reservation must fit. The current public runtime exposes no tokenizer, so all token figures are estimates. Plan pages return at most 50 items and 32,768 UTF-8 bytes; complete planning packets are limited to 196,608 bytes. Plans are Host runtime state and are not restored after restart. A budget-ready plan is not executable; planning does not accept a translation unit, consume a draft or material, or dispatch a translation request. `sourceRef` execution still returns `requires_batch` until batch execution is implemented.
- Each admitted text unit keeps all translation revisions. Retranslation reuses that unit's source, language and requirements with the currently selected model; it leaves any new draft untouched. Previous versions can be expanded, and one complete version can be selected as final.
- Manual editing saves a new revision with its original base version, without calling a model; choose to keep it as the latest candidate or finalize it immediately. Session context actions export final translations as TXT or source/final translation pairs as bilingual JSON.
- Translation records can link manually selected originals at fixed character positions. Source and result may share one original or open separate fixed files for the same object. Optional TeX source uses the native formula preview, with the source and original always available.
- **记忆资产 (Memory assets)** opens an independent tab, initially as a DSH application floating panel. Text translation records pair read-only source and final translation in continuous rows. Document records show source and result in continuous columns in plan order; each side loads bounded pages on demand and keeps missing or unknown blocks in place. **打开原稿 (Open original)** and **打开结果 (Open result)** share the document-opening workflow: saved managed originals use the source store, while inline or runtime text is assembled from bounded pages as a browser text projection; text results are rebuilt from the frozen final manifest. The open actions remain available to retry after an error. Both record types have an independent session/topic scope.
- Document TXT and JSON exports freeze the selected session or topic, source versions, final versions and manifest before reading bounded pages. Missing ranges require an explicit choice to export partially; TXT follows manifest order without added paragraph separators and marks each gap with its source code-point range and reason. Document JSON uses schemaVersion 3 and carries the source, final revision, manifest and ordered blocks; partial output sets `complete:false` with `missingRanges`. Existing short-text TXT and JSON v1 exports (v2 when linked objects are present) remain compatible. The structured archive provides terminology, entities, facts and relations, including manual creation/editing, evidence, search, status filters, adoption, disable and deletion. Scoped main-model tools use the same authoritative browser stores; Quick translation does not use these assets.
- Main-model session tools create sessions in the background, rename a topic, change an individual remark and archive or restore an explicit session. **记忆资产 (Memory assets)** is the first item in the title dropdown, followed by session selection and creation. The asset window's searchable topic picker includes retained topics without sessions; JSON and Markdown export the topic's complete existing terminology and structured archive together.
- **DSH Settings → 翻译** provides new-session defaults, history retention and history cleanup. Valid changes save immediately.

Quick translation and Normal short-text execution use models configured in DSH. Normal mode can submit text or one TXT, including automatically packaged long text, for main-model discussion and task preparation, but whole-document translation is unavailable. Normal submission requires the host Composer extension below. Quick uses only its built-in prompt, source, target language, explicit requirements and selected model; it excludes tools, main conversation, old translations, files and memory. Unknown outcomes retain the original operation for queries and are not automatically resent.

The panel keeps a simple composer and transcript. Main-model archive management, material submission, Normal short-text execution, independent terminology analysis, task preparation and runtime-only document plan validation are implemented. A TXT, including automatically packaged long Normal text, can be submitted as a referenced source for discussion, preparation and planning. A plan with a valid budget is not a translation task and cannot yet execute. Planning tools require the existing v2 main-model tool connection and an available prepared translation model. Full main-Send integration depends on the host extension below. Main-chat backup, whole-document execution and changes to an admitted unit's target language or requirements remain unavailable.

**重新检查翻译服务 (Check translation service again)** only queries whether the DSH Host translation service and runtime components are ready. It sends no source text or model translation request and does not test model credentials or remote responses. The Client waits for DSH's asynchronous service mount before querying capabilities, avoiding a false unavailable status while the service is still mounting.

## Normal submission materials

The plugin implements synchronous draft capture, a Host preparation acknowledgment before main submission, and direct material submission. These controls require matching Composer protocol v1 support from the optional `dsh-composer-extension` Client adapter or the native `conversation.submissions` seam. The Client registers through only one path and rejects an unversioned seam. Official DSH `0.2.0-rc.2` does not provide either path: the panel explains the missing capability and disables Normal Send. Installing this plugin alone does not add host support.

With that extension available, the main composer shows the active Normal material, including a selected TXT. One main Send action freezes either the text or file together with its target language, explicit requirements, model selection and character limit, waits for Host preparation, then attaches a separate **待译材料 (Translation material)** message to that same main request. If both a file and non-empty text are present, choose one before submitting. **本次不附带 (Omit this time)** skips the material and does not upload its file; the original main command stays unchanged. The Normal panel's Send button can submit the material directly without an additional main instruction, including when the main composer is empty. Both paths retain the selected file and text typed after the snapshot; direct submission also leaves the main-composer draft untouched. A translation-model selection may be empty when submitting material for discussion. If upload or preparation fails, the selected file and draft remain available.

Material submission delivers the frozen source to the main conversation for discussion and records main admission. Host preparation checks that a TXT source reference and all frozen metadata belong to the correct scope, owning main conversation and Agent/Peer. The main-model notice carries the file reference, length and configuration, not the file body; the existing `translation_read_source` tool reads it in ranges. Business admission is separate: eligible inline-text materials can create a unit and consume only the unchanged submitted draft; later edits remain intact. Task preparation is also separate from business admission and does not create a translation unit or revision.

For an inline short-text translation, the main model calls the Normal execution tool for delivered material, organizes requirements and selects effective terms by ID/version. The Client supplies authoritative terminology; adopted user rules stay fixed. After preflight and business acceptance, the translator streams into the original unit using the frozen model, language and user requirements. A TXT `sourceRef`, including one created automatically from long Normal text, is available for preparation and discussion only; the short-text executor rejects it before business admission or model dispatch because whole-file translation is not connected. Discussion alone preserves the draft and creates no unit. Submission and admission receipts do not mean translation is complete; unfinished units remain missing from final exports.

When the matching `dsh-composer-extension` Host exchange service is registered, the main session connection negotiates v2, and the translation route supports tool calls, the translator may use its restricted `request_context` tool to ask up to three range-scoped questions. The owning main Agent can answer, defer or abort. An answer resumes the same operation with the frozen source, model and requirements but a new call; a second context request waits for the user. A late request does not wake a main Agent stopped by the user. Older connections and routes without tools retain text-only translation. These checks use synthetic providers; real desktop and model combinations are not yet verified.

Records provide **查询普通执行状态 (Query Normal execution status)** and **取消普通翻译 (Cancel Normal translation)**. Failed or cancelled calls retain partial output and actual call facts. Reloaded records can apply missing events while Host retains the original operation; unavailable outcomes remain explicitly unknown. Queries never repeat the provider call. A normal operation uses one short-text call unless bounded context exchange enables one resumed call; a `sourceRef` execution still returns `requires_batch` before admission or model dispatch. Independent terminology analysis and task preparation are available for delivered material. The main Agent can also validate a runtime-only document plan and inspect its capacity budget; this does not call the translation model or create a translation unit. Whole-file translation, batch admission and block execution remain unavailable.

For delivered Normal material, the main model can call `translation_read_source({target, range})` to read `[start, end)` Unicode-code-point ranges of up to 4,000 code points; the complete serialized response is limited to 32,768 UTF-8 bytes. The tool checks the exact material and source version plus owning Agent/Peer, reads source only, and does not call an LLM, change drafts or create units. TXT notices carry configuration, fixed reference and length rather than the file body. Long Normal text is automatically uploaded as TXT and uses this reference approach when it exceeds 8,000 Unicode code points, the session's single-input limit, or 196,608 UTF-8 bytes as an inline material envelope.

Source reading and plan validation do not add whole-file execution. `sourceRef` execution returns `requires_batch` before business admission or a model call; the scheduler and block execution are not connected. Normal material submission still requires the host `ctx.conversation.submissions` extension, which official DSH `0.2.0-rc.2` does not include. Bounded context exchange applies only to inline short text and permits at most one resumed call.

Each request keeps its first frozen snapshot. Later edits do not change it. Material identity, editable draft version and submitted source version are separate. When history is enabled, saved document records retain each source version as inline text or a managed source identity; raw TXT bytes are excluded from browser history. A runtime-only source or unsaved change is not a promise that an original file survives restart. **Open original** uses a saved managed source when available, or builds a paged text projection for inline/runtime content. The submission notice and source pages read by the main model may appear in DSH's main-conversation and model-request records; original attachments follow DSH's own retention policy. The plugin history switch does not control or remove those DSH records or attachments. An unknown outcome retains the request identity for queries and is not automatically resent.

Normal material can be either inline text or one `.txt` file, not both. Text exceeding 8,000 Unicode code points, the session's current single-input limit, or **196608 UTF-8 bytes** as an inline material envelope is automatically sent through DSH's native TXT upload path and delivered as a fixed source reference; no separate file save or extra confirmation is needed. Automatically packaged text must be valid Unicode and no larger than **2 MiB UTF-8**. An unpaired UTF-16 surrogate is rejected with a clear error while the draft is preserved; source text is never truncated. Manually selected files must be valid UTF-8 and no larger than **2 MiB**; BOM and CRLF are preserved. **Omit this time** skips the material without uploading the selected file. The main model reads TXT source in bounded ranges for discussion or preparation; complete-file and batched translation remain unavailable.

## Retranslation and final versions

1. Select a configured model and reasoning effort, enter source text and click Send. Business admission creates one text unit. Retranslation keeps its selected source version, target language and requirements.
2. Click **重译 (Retranslate)** on that unit to produce another revision with the current model and effort. The new revision records this operation's model selection and time; any text in the composer remains a separate draft.
3. Click **展开旧版本 (Expand previous versions)** to read earlier results and status; **收起旧版本 (Collapse previous versions)** hides them again. **详情 (Details)** shows model, effort and times, plus prompt version and token usage when reported. Older records without call evidence show only the selected model; missing counts display “未提供” (Not provided), while reported zero stays zero. Reading or copying a version does not select it as final.
4. On a complete version, click **设为最终 (Set as final)** to fix that choice. Later trial translations keep it until you explicitly select another complete version.

When the next text unit is admitted, the immediately preceding unit's latest complete revision becomes its automatic final version, including a saved manual revision. Typing a draft, switching sessions, archiving or closing the panel does not finalize it. If the latest attempt failed, is incomplete or has an unknown outcome, the plugin does not silently choose an older success; an existing final selection is preserved. A historical unit's retranslations remain candidates until explicitly selected. Exporting TXT or bilingual JSON applies the same automatic rule to the last unit of each included session only, preserving user-fixed choices. Final selection does not call a model.

In Normal mode, **重译 (Retranslate)** explicitly shares that unit and sends a retranslation intent to the main model. The main model calls the execution tool, which appends to the same unit using the translation session's current model and effort frozen at preparation. Later model changes do not alter that call; composer draft B stays intact. This also supports older Quick records after upgrading their session to Normal. Other unshared history remains unavailable to the main model.

For a unit already shared with the main model, request source correction in the main conversation. The correction tool checks the expected source version and appends a complete new source body without overwriting earlier versions. Correction alone does not run translation; an instruction to correct and translate uses separate correction and execution operations. Expand source versions to review the originals. Revisions and manual edits based on an older source are marked outdated, and an old fixed final remains traceable but cannot form a current-source export pair. Current-source results can replace that old pointer through the existing selection rules; a current-source user-fixed final remains protected. Late old-source output stays in its old revision. Source-linked objects block automatic correction; translation-only links do not.

## Manual revisions and export

1. Click **编辑 (Edit)** on a nonempty ended version: completed, failed, cancelled or interrupted. Edit its translation, then choose **保存最新版本 (Save as latest)**, **保存并定稿 (Save and finalize)** or **取消 (Cancel)**. The first appends a candidate and preserves the current final selection; the second appends a revision and selects it as final, and is available only when its base uses the current source version. A partial ended result can be corrected into a complete manual version. The new version records the displayed base version and does not change the unit's source, language or requirements. A later model result never silently changes that editing base.
2. Saving without finalizing creates a candidate; **设为最终 (Set as final)** can explicitly fix it later. A candidate can also qualify for automatic selection when the next unit is admitted or TXT/bilingual JSON closes the last unit. Manual versions have no model call, route or usage. Unsaved editing drafts remain only in the current runtime, including while switching sessions, and are lost on reload.
3. Right-click the session title or name and choose **导出译文 TXT (Export translations TXT)**, then **当前会话 (Current session)** for the clicked session or **整个主题 (Entire topic)** for all sessions in its topic, including archived sessions. The export closes only each included session's last unit and joins final text in fixed session-sequence and text-unit order. Missing finals are listed by session and text number; choose **仅导出已定稿 (Export only finalized units)** for a frozen partial file or cancel. Failed or partial output is never substituted for a final, and an export with no final translations is unavailable. An empty clicked session can still export its topic when other sessions have text records.
4. Choose **导出对照 JSON (Export bilingual JSON)** and the same scope options for source/final translation pairs, grouped by session with its name, remark, fixed sequence and export time. It applies the same last-unit finalization and missing-final confirmation as TXT. Missing entries stay labelled with `translation: null` in a partial file. Drafts, revision history and call metadata are excluded. JSON import or restore is not provided.
5. In **记忆资产 → 译文记录 (Memory assets → Translation records)**, choose **当前会话 (Current session)** or **当前主题全部会话 (All sessions in the current topic)**. **导出 TXT (Export TXT)** and **导出 JSON (Export JSON)** use that same viewing scope, including archived sessions in topic scope. They use the same finalization and frozen missing-final confirmation rules; hover over either button for its exact scope and contents.
6. Document exports use the current session or topic scope. Before loading pages, the plugin freezes the source versions, final versions and manifest for that scope. If ranges are missing or unknown, choose whether to export partially. TXT follows manifest order without adding paragraph separators and inserts a missing-range marker with the original code-point range and reason; complete TXT retains object placeholders, while a partial export marks object links whose position cannot be determined. Document JSON schemaVersion 3 includes source/sourceVersion, finalRevisionId, manifestRevisionId, the fixed manifest and ordered blocks; partial output sets `complete:false` and `missingRanges` and retains fixed object references. A gap is never omitted and presented as a complete result.

Editing, final selection and export do not call a model. Upgrading a Quick session to Normal keeps its existing plain-text records editable and exportable, with historical retranslation available through the main model. A revision with linked objects cannot currently be edited; a link on the source alone does not prevent editing its plain-text translation. Explicit export also works with history retention off. Export does not enable history retention or create an additional automatic history store; persistence of the final selection follows the existing retention setting. Save the exported file through the browser. The UI reports that the browser download was initiated, not that a file was saved.

### Linked originals in translation records

Expand a unit in **记忆资产 → 译文记录 (Memory assets → Translation records)** and use **关联原件 (Link original)**. Select source or an ended translation version, an original type and a file; the default position is the end of its text, or specify a character position. The record displays links such as `[图片1]`, `[表格1]`, `[代码1]`, `[公式1]` or `[文档1]`. These come from separate reference metadata; the original text is unchanged, and typing those markers does not create a link. Existing positions remain fixed. Archived sessions must be restored before adding a link.

For a translation, **沿用原件 (Reuse original)** keeps the exact source object and file version. **结果新文件 (New result file)** registers a separate fixed file for that same object. Clicking a link asks Host to open its managed original through the system's associated application; unavailable files or failed opens remain on that target and can be retried. Embedded objects can be linked to their original document; automatic document parsing, embedded-object extraction, thumbnails and redrawing are not provided. Text code and character formulas stay readable text. When reliable TeX source already exists, optionally enter **公式源 (Formula source)** to try the native formula preview; the source and original link remain available even when it cannot render correctly.

Original files and their opening index remain stored in DSH after explicit linking. Only the record's association positions follow the session-history setting; turning it off does not remove registered originals. This manual linking action is separate from Normal TXT material submission, which supports discussion, preparation and planning but not whole-file execution. TXT exports preserve object markers; bilingual JSON adds fixed object-reference metadata without embedding file bytes. The export is not an original-file backup or an import format.

## Topic archives and main-model access

Choose **记忆资产 (Memory assets)** at the top of the title dropdown, or choose **记忆 (Memory)** in a session's context menu. Search topics using the small gray topic name in the floating title bar or the compact topic menu in the docked view's body, including retained topics with no sessions. Both use the owning main conversation's topic scope; selecting a topic changes only the asset view. Sessions in the same stable topic share terminology, entities, facts and relations; renaming keeps that identity, and a new topic starts empty. Entries may be proposals, active, awaiting review or disabled; terminology also tracks conflicts.

The asset view keeps its owning main conversation fixed; opening memory assets again reuses its tab and selects the requested topic and associated session. A new view floats within DSH when its owning conversation is visible; an existing or restored tab keeps its docked/floating state. The floating title shows fixed bold **记忆资产**, the remark or session name in regular weight, and a smaller gray interactive topic selector together, without an extra narrow width limit; long names truncate when space runs out. A retained topic without a session shows **无关联会话 (No associated session)**. Docked tabs show only **记忆资产**, with topic navigation in the body. The host's controls remain in place, and the body omits the duplicate context heading. Title text and empty space remain draggable; interacting with the topic selector opens its menu. Use the host's controls to close, dock, move or resize the application floating panel; no additional body close button or Windows native child window is provided. Topic, category and entry switching retain drafts only while their views stay mounted; closing or reloading releases the viewing state and drafts, leaving assets intact. Switching away from the translation tab keeps its manual-edit drafts mounted.

Choose **结构化档案 (Structured archive)** and use **档案类型 (Archive type)** to select terminology, entities, facts or relations. **译文记录 (Translation records)** initially shows the explicitly associated session; without an associated session it uses topic scope. Choose another session from the same topic or switch to **当前主题全部会话 (All sessions in the current topic)**, including archived sessions in fixed session-sequence and text-unit order. This viewing selection does not follow or change the translation workspace's active session. Opening the asset tab explicitly again adopts the requested associated session. Each unit pairs its read-only source on the left with the current final translation on the right in one continuous scrolling area; a narrow view stacks source above final translation for that same unit. When no current final exists, the latest complete candidate appears directly in the final pane; if a final and a newer candidate coexist, both remain visible and clearly labelled. Copy and edit actions stay beside each version. Editing is anchored to the selected final or latest candidate and opens inline; **保存最新版本 (Save as latest)** appends a candidate while preserving the current final, and **保存并定稿 (Save and finalize)** appends the edited version and selects it as final. Expanding a unit still shows prior source versions and linked-original details. The view does not skip a newer failure to show an older success. Source text and machine execution records are not rewritten. Archived records remain readable; restore their session before editing. Each mounted topic keeps its range, selected session, scroll positions and unsaved drafts across topic/category changes; none of this viewing state is saved after closing or reloading. Structured archives always remain shared by the selected topic. **其他记忆 (Other memory)** and **临时文件 (Temporary files)** remain unavailable.

In the structured archive, click **新增术语 (Add term)** or **编辑术语 (Edit term)** and edit the original term, translation and optional explanation. Most terms can leave the explanation empty; provide context when needed for an author's original concept. New explanations start collapsed; existing nonempty explanations open for editing. New terms use the associated session's target language. Editing preserves existing languages, aliases and avoided translations. **保存并采用 (Save and adopt)** establishes an explicit user rule in one action, preserving ID, creation time and source examples. Stale or conflicting saves retain unsaved input. Models cannot overwrite confirmed user rules.

Use **新增实体 (Add entity)** for a name, aliases and description; **新增事实 (Add fact)** for a title, fact content and linked entities; or **新增关系 (Add relation)** for a source entity, relation, target entity and description. Saving and adopting establishes an explicit user entry. Entity links must stay within the topic. Changing, disabling or deleting a referenced entity sends dependent facts and relations for review instead of silently redirecting them. If another window deletes an entity, fact or relation being edited, its unsaved draft remains available to copy, with saving disabled.

Search and status filters affect only the selected type's list, excluding evidence bodies; exports include the complete topic snapshot. Terminology search matches forms, aliases, preferred/avoided translations and sense. The list and details scroll separately in a wide view and use a single column in a narrow view. Filters last while the view remains mounted, without persistence after closing.

Topic-management tools belong only to that main conversation's Agent and communicate with the browser through a bidirectional bridge: list topics/sessions, create a session, rename a topic, set a session remark, archive/restore a session, read explicitly supplied historical units, list/query/submit terms, and list/query/submit entities, facts and relations. Archive listing and submission take an explicit topic ID, including a retained topic with no sessions. Queries derive the topic and actual mode from the identified translation session. These management tools do not directly delete sessions or archive entries, edit drafts or model selections, change defaults or upgrade a mode.

Session creation takes an explicit starting point: a new topic, a parent session or an existing topic. A new topic is used when expressly requested by the user; the model may organize same-topic sub-sessions within the work already assigned, without an extra confirmation each time. A parent-based session inherits its configuration with an empty draft and remark; an existing topic uses an available session's configuration, or current defaults when none remains. Creation and restoration keep the user's current focus. The creation reason appears in the tool receipt and is not copied into the remark. Rename affects all sessions in the identified topic; remark and archive changes target only the identified session. Expected names, remarks and archive states are checked under the existing topic lock. Receipts distinguish saved changes from runtime-only changes; a save failure reports that memory may already have changed and should be queried, without claiming a rollback.

Inferences remain proposals. A source-checked entry with readable source evidence and no conflict can become active directly; a proposal requires the explicit **采用 (Adopt)** action. Adopted user rules cannot be overwritten by a model. Resolve conflicting rules explicitly; the newest suggestion does not win automatically. **停用 (Disable)** keeps an entry for reference; **重新采用 (Adopt again)** explicitly reactivates it subject to conflict checks. **删除 (Delete)** removes the selected shared entry after confirmation.

Evidence references the existing source or final translation without copying its body into the archive. Model submissions can cite only historical units explicitly supplied by the user. A changed/deleted basis becomes unavailable and its derived entry awaits review; queries exclude it immediately. Final evidence includes the final-selection event, so selecting the same old revision again does not revive an old basis. Losing a source example does not revoke an independently adopted user rule. Terminology lookup matches explicitly requested source forms or aliases within the same owner, topic and languages. Entity/fact/relation lookup matches names, aliases, titles, relations or linked active entity names; it does not infer entries from arbitrary substrings. Quick lookup is empty, and Quick finals do not automatically extract archives.

For optional discussion of existing history, a session upgraded to Normal can expose an ended text unit through **供主模型参考 (Provide as main-model reference)** and withdraw it through **取消参考 (Cancel reference)**. This shares only the selected unit's frozen source, requirements, revisions and final metadata, not the current draft or unselected history. The reference selection lasts for the current runtime; **更新主模型参考 (Update reference)** refreshes that selected snapshot. This optional history-sharing action is separate from the draft attachment described above and does not send a translation request.

History retention also controls terminology and entity/fact/relation persistence. Enabling it saves their independent topic snapshots; disabling it preserves old copies and keeps subsequent edits only in the current runtime. Re-enabling saves contents still in memory. Read/write failures retain current input and facts; conflicts require explicitly loading the latest copy. A save failure can leave memory changed without updating storage; query the current version before retrying. Archives contain no duplicate source/final bodies, main-chat backup, Host capability or credentials. Session TXT/bilingual JSON exports do not include these separate archives.

### Export a topic-archive snapshot

Open **记忆资产 (Memory assets)**, choose the topic and open **结构化档案 (Structured archive)**, including for a topic whose last session was deleted. **导出 JSON (Export JSON)** and **导出 Markdown (Export Markdown)** freeze its complete current terminology, entity, fact and relation snapshots together, regardless of the selected type or list filters. They retain all statuses, content, versions, adoption records, update/export times, entity links, evidence references and availability labels. Pending, conflicting, unavailable and disabled entries remain labelled as such.

The file contains existing archives, without evidence bodies, main chat or a complete topic backup. Export does not call a model, extract or organize entries, change archives or final selections, enable history retention or create another automatic history store. It also works when retention is off. JSON import is not provided. Save the file through the browser; a download notice does not confirm that it was saved.

## History and deletion

History and model preferences use the current device and Web origin's `localStorage`. Records are plaintext, are not synchronized between devices, do not modify the Host profile patch, and contain no API keys or Host capability handles. When **允许保存会话历史到本地 (Allow local session history)** is enabled, history stores topic/session identities, fixed sequences, names, remarks, archive status, the current source draft and default snapshots, plus admitted text units' source text and document units' source versions (inline text or a managed source identity), requirements, language, revisions, execution status, safe actual call metadata and final selections. Saved document history retains each source version as inline text or a managed identity, not raw file bytes. Each revision body is stored once; events and final selections reference it. Unsaved editing drafts are excluded.

Restoration does not resume or resend model requests. Previously running revisions show **重启前未确认／已中断 (Unconfirmed before restart / Interrupted)**. Normal records, including accepted units with no call, can query the original operation and apply missing events from the last saved sequence while Host still retains it. Unavailable results remain unknown; queries do not regenerate text. Restored Quick records cannot query the previous Host operation. Raw file bytes are excluded from browser history; document units retain each source version as inline text or a managed identity. The plugin does not back up DSH model-message history; submitted Normal materials can enter DSH records independently of this setting.

Disabling retention preserves existing history while subsequent renames, new units, revisions and final selections remain in the current runtime and do not replace saved copies. Independent model preferences continue saving and contain only the provider ID, model ID and optional reasoning effort. They give recoverable sessions their latest choices without rewriting old history content. Deleting a session removes its own preference; history cleanup preserves the last model preference for its owning main-window conversation as a default for new sessions. Previously saved topics retain identity and sequence metadata without source or result content, so issued numbers are not reused after restart. Entirely temporary new topics do not become persistent for this purpose. Re-enabling retention saves current content still in memory, including changes made while it was off; it cannot recover content already lost. Settings provides:

- **清除历史快译**: delete saved quick-translation sessions.
- **清除所有会话历史**: delete all saved plugin sessions; the confirmation scope includes unreadable history copies.
- **删除所选历史**: select one or multiple sessions for deletion.

Deletion requires confirmation and removes the affected sessions from the list. Context deletion handles both current in-memory content and saved history. Deleting a session does not cascade to its parent or children. History cleanup includes archived records. Topic terms remain by default, including after the last session is deleted. To remove them too, explicitly check the confirmation's shared-topic terminology option; unselected sessions in those topics also lose those terms. Both session and term versions are frozen and checked before removal. Partial failures report the remaining scope; multiple storage removals are not claimed as atomic.

Entities, facts and relations are retained independently. Session deletion, history cleanup and the shared-topic terminology checkbox do not remove them. Delete their entries explicitly in Memory assets; this remains available with history retention off and does not save other temporary edits.

Persistent topic creation, numbering, renaming and related writes use browser Web Locks for coordination. Environments without safe coordination report the limitation and restrict affected persistent operations; entirely temporary content can remain in the current window. Locks coordinate windows participating in this version's protocol; they do not turn multiple `localStorage` writes into a database transaction.

Read and write failures preserve current input. Stale writes produce a conflict; loading a local copy requires confirmation and overwriting is explicit. Partial cleanup reports an incomplete result, and deletion records prevent automatic re-import of old copies. Deleting all sessions does not reset a retained topic's sequence. If history saving is turned off, existing preparation audits remain and new versions are runtime-only. After it is turned back on, the next successfully saved preparation version also saves earlier versions still available in the current run.

Saved v1 drafts and schema2/3/4/5/6/7/8/9 sessions remain readable, including history1/2/3/4/5/6. Confirmed parent relationships group old sessions into topics with a unified sequence; old display names remain available. Uncertain relationships stay separate. Migration does not reconstruct deleted numbers that the old version never recorded. Compatibility reads do not rewrite saved content; schema10/history7 is written only when a history change is explicitly saved, while empty records still use schema3. Text units retain their prior record shape. Document units store each source version as inline text or a managed source identity and keep preparation, plan, chunk revisions and manifest as references; manifests do not duplicate the assembled document text. Each revision references its source version, and exchange questions/answers are stored once in exchange records. Task-preparation audit snapshots use an independent schema 1 store and do not migrate session history. Versions before v0.15.3 cannot read schema10; back up the application's local data before downgrading, and avoid modifying the same history with older versions. A saved preparation audit is readable only while its owning translation session exists; it does not restore its runtime-only source or candidate catalog and cannot resume analysis, editing or execution. Exported bilingual JSON is a source/final comparison file, with no import/restore feature, and does not replace that backup.

The old manual-save preference does not automatically enable new automatic history retention; the new option starts off. Disabling or uninstalling the plugin does not delete local history, archives or preferences. Clean up explicitly before removal when needed.

## Compatibility and installation

The plugin targets DSH `0.2.0-rc.2` components. Automated checks cover Quick Host/Client, mounting, scoped topic tools and storage, using a disposable synthetic profile and provider. UI and browser-download checks are simulated; Menu/Sidebar contract checks use installed component logic with synthetic dimensions and actions. Original-file checks use DSH's upload and attachment services with a simulated final system-open result; formula checks use the installed renderer in an isolated browser. These checks do not cover real remote providers, actual Desktop DOM, file-save dialogs or floating-panel movement, resizing and docking. Other DSH versions, operating systems and standalone Web profiles are unverified. Windows native child windows are unavailable.

Requirements: Node.js 22 or later, pnpm and DSH with local bundle support.

```powershell
pnpm install --frozen-lockfile
pnpm build
```

Install this directory as the `dsh-translation-plugin` local bundle in DSH's plugin manager, enable it and restart. Runtime artifacts are generated into `dist/` and are not committed. Rebuild the same directory after changes to a linked installation. Upgrade to v0.17.1 with matching Host/Client bundles; refresh the Client registration (or reinstall if refresh is unavailable), then restart. Normal material controls require a Composer protocol 1 host, and context exchange requires `dsh-composer-extension` v0.2.0; official DSH `0.2.0-rc.2` does not provide the submission interface. Task-preparation and plan-validation tools register on the existing protocol 2 topic bridge to the main Agent. The separate extension-provided phase notification contract remains `phaseProtocol` 1; this release does not change Composer protocol 1, Exchange protocol 1, Normal protocol 2 or Remote v1. Without extension 0.2.0, analysis status and candidates can still be queried but the main Agent is not automatically notified. Saved document history continues to use schema10/history7; task-preparation audits use an independent schema 1 store and add no session-history migration. Older formats remain readable. Terminology and archive schemas stay at 1, and object-position namespaces are unchanged. Back up application data before downgrading; v0.15.2 and earlier cannot read schema10 history.

When upgrading from an early framework build, refresh the bundle metadata containing the model catalog RPC dependencies in the plugin manager; if refresh is unavailable, uninstall and reinstall, then restart DSH. Do not edit the profile manually.

If previously installed as `dsh-deepseek-translation-plugin`, remove that old bundle and reinstall. For startup failures, use Desktop's recovery option to disable third-party plugins and inspect the diagnostic log.
