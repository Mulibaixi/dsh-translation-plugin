## 环境与依赖

- DSH `>=0.2.0-rc.2`，支持本地插件、具备所需接口，并已配置可用模型；不逐项列举兼容版本。
- **快译**不要求 Composer 扩展；**普通模式**需要配套的 `dsh-composer-extension` 及 submissions protocol 1。宿主已有该接口时直接使用；缺少时，Windows 桌面版按目标模块指纹匹配随包补丁，正常完全退出后安装，重开生效。
- 配套源码使用内容协议 3 和任务阶段协议 2。升级 DSH 后查看扩展的联动组件维护状态；相关模块不变可复用补丁，无需仅为版本号变化更新插件。所需接口或补丁目标改变时才需要适配。
- 文件候选资产提取使用 DSH 原生子代理，适配受支持版本的 run／Activation 接口；能力缺失会提示原因，主模型仍可直接读取文本原稿并翻译。
- 宿主需能加载内置 `node:sqlite`；从源码构建需要 Node.js 22 或更高版本、pnpm，以及并排放置的 Composer 扩展源码目录。

当前文件翻译主要支持 UTF-8 编码的 TXT／Markdown，每份最多 2 MiB，可按原格式交付。其他格式仍依赖主模型使用自身工具读取或识读，插件尚未提供 PDF、图片、DOCX 等格式的完整解析、OCR 与原格式还原流程。JSON／HTML 结果可按约定形式保存；参考全文的可读格式见下文。

记忆资产窗口位于 DSH 应用内，可浮动或停靠。

## 主题与会话

首次打开选择**新建主题及首会话**或**选择已有主题**。主题归集同一故事或项目的记忆资产，翻译会话分开处理具体材料。同一本地资料库可在不同主聊天中继续使用；没有当前主聊天时也可浏览和管理已保存资料。

- 标题下拉中的 **+** 创建新主题及首会话后自动进入重命名，取消则保留默认名称。右键会话或主题，直接点击**新建**沿用原有配置和模式继承规则；悬停或点击右侧箭头，可选择**新建快译会话**或**新建普通会话**，在同主题下使用不同模式。
- **重命名**修改主题名；**备注**只修改当前会话的显示名称。长按会话行后拖动可排序。
- 右键主题，悬停**打开**或点击右侧箭头后，在会话列表中选择目标。子菜单向右、向下展开，靠近窗口边缘时自动避让；键盘右方向键进入子菜单，左方向键返回父项。
- **关闭**移出当前主聊天的打开列表；**归档**保留资料；**删除**清除内容并要求确认。

模型选择位于输入框右下角，目标语言和模式位于顶部。会话可以从快译升为普通；需要改回快译时另建会话。单元编号稳定，删除后不回填空号。

## 快译

选择快译模式、目标语言和模型，填写纯文本后发送。快译不读取主聊天上下文、主题记忆或参考资料，也不接收文件；需要术语一致性或背景资料时使用普通模式。

## 普通模式与材料提交

**翻译输入框放原文，主聊天输入框放要求和讨论。** 先在当前主聊天中打开要使用的翻译会话，再选择发送方式：

- **连同要求发送**：在工作区准备文本或文件，在主聊天写明本次要求并发送。材料默认用于翻译；本次明确要求学习、讨论或暂不翻译时，按该要求处理。
- **直接发送材料**：点击工作区的发送按钮，请当前主模型翻译。主聊天输入框中尚未发送的文字不会一并提交。

材料发出后继续编辑输入框，不会改写已发送的原稿。原文纠错或修改译文时，在主聊天明确指出对应单元和要求，例如“参考单元 2、4 的用词，修改单元 5”；跨会话时附上会话名称。主模型可按需读取已打开会话的原文、定稿或指定版本。

普通文本和文件统一通过当前翻译流程处理。长原稿可按原文范围分段，结果须连续覆盖全文；主模型等待实际结果，先独立通读译文，再对照原文核验语义与表达，必要时在同一单元追加修订。

重译、材料发送和原文嵌入会明确本次动作与对象，主回合被中断后不会因此授权恢复旧任务；后台翻译状态仍以实际操作回执为准。当前动作明确时无需重复确认；如果存在真实指令冲突、无法确认任务或对象，主模型应先说明冲突并询问你，不能自行选一项继续。主动加载工具和必要的身份／状态读取仍可进行。随主聊天附带的材料遵从当条用户指令，不会把明确的学习或讨论任务改为翻译。

### 文件交付

文件原稿和各版译文显示为文件入口。TXT／Markdown 译件跟随原格式，默认通过会话交付，打开时生成可读文件名，同版重复打开复用同一份文件；只有明确要求独立导出时另存。文本结果保留原稿 BOM 和统一 CRLF 换行。JSON、HTML 等未指定输出形式时会先询问。

### Markdown 与本地图片

Markdown 翻译和审阅要求保留标题、列表、表格、代码及公式结构，目录和文内锚点由主模型复查；仍需人工核对实际显示与跳转。桌面上传会保留原 MD 的本机位置，打开／导出时把标准 Markdown 相对引用的本地图片复制到 MD 副本旁，并使用相对链接，记录正文仍保留原引用。生成副本时原图片须可读取；移动或分享译件时须连同旁边的图片一起保留。Web 上传没有来源位置时保留原引用。本阶段不处理图片内文字、HTML 图片引用或整个资源目录打包。

### 上下文与任务恢复

普通翻译读取适用设定与选定记忆。短文本可自动匹配参考原件中的相同表达；相似译例、长文件和背景事实由主模型检索、读取并选入上下文。修订携带准确旧译文，邻近对白使用有效最终版本；检索命中不等于一定正确采用。

普通翻译中，支持工具调用的翻译模型可在缺少关键语境、术语有歧义或要求冲突时提出 1～3 个具体问题。主模型先结合已有要求和可访问资料回答，确需用户决定时再询问；补充后重新调用翻译模型，取得完整译文并继续审阅和交付。提问前生成的部分文字不作为候选译文保存。

主模型默认最多自动补齐一次；仍有关键疑点时交用户决定，不连续重试。补充调用会保留先前的问答、用户要求和背景；等待期间原稿、有效译文或人工定稿变化时，先核对当前内容再重新组织任务。需要排查时，可请主模型读取该次问题或译文的实际调用日志。

提问和补充后的翻译分别产生实际调用及用量。问题引用仅在当前宿主运行期有效；重启后已有单元可重新读取，尚未形成结果的材料需按现有入口重新提交。所选提供商和模型须支持工具调用；工具声明被拒绝时报告错误，不静默重试为普通翻译。明确要求翻译前先澄清时，由主模型先询问。

撤回材料会通知主模型后续步骤；已执行的任务使用取消入口。重载后中断或结果未知时，先使用查询、取消或重译入口核对原任务，避免重复调用。重启不自动续跑模型请求，任务也不自动转交其他主聊天。

## 记忆资产

从标题下拉的**记忆资产**或会话右键菜单进入，可切换查阅主题，不改变工作区当前会话。也可在主聊天提供资料并要求“学习资料”或“建立主题记忆”，由主模型读取实际材料、保留依据、检查已有内容并建档，无需先翻译文件。

参考文件在**其他记忆**管理。术语与档案的单元依据只引用实际原文或定稿；主聊天附件学习得到的条目先作为候选保存，采用前须审阅。

| 类别     | 保存内容                                                       |
| -------- | -------------------------------------------------------------- |
| 术语     | 原词、译法及必要的含义或使用条件。                             |
| 实体     | 人物、地点、组织等，以及别名和描述。                           |
| 事实     | 主题中的重要事实，可关联实体。                                 |
| 关系     | 实体之间的联系，包括人物称谓及适用条件。                       |
| 其他记忆 | 源文之外的主题级／用户级翻译设定，以及主题原文／双语对照文件。 |

四类档案中的条目可查看依据、新增、编辑、采用、停用或删除。主模型可修改已有条目；内容改变后回到待审阅，相同内容保留状态。冲突或依据变化时需复核。同主题会话共享资产，不同主题独立管理。

主模型写入术语或档案后，收到本次写入结果、准确版本和条目状态；实体修改涉及的关联待复核条目会一并说明。写入回执不重复整份资料，完整内容仍可在界面、查询和导出中查看。

候选直接保存在相应类别中。**一键采用**处理当前主题、当前类别的全部待审及待复核条目，不受页内筛选影响；事实和关系的关联实体须先采用。暂不能采用的条目保留并显示未完成数量，候选不阻碍译文交付。

翻译采用优先级为：**用户指令 = 用户编辑确定的条目 > 用户审阅通过的条目 > 待审条目 = 模型理解**。用户指令与用户编辑条目冲突时请求指示；候选不会自动覆盖已生效资产，模型整理的说明也不会变成用户指令。

### 翻译设定

**翻译设定**可新建、编辑、启用、停用或删除，也可由主模型维护。普通翻译及重译完整读取全部适用的启用条目；用户级适用于当前本地资料库，其他要求默认当前主题。规则应精简、准确、保留适用条件，避免将单句修改、偶然译法或模型自检固化为通用要求。超过调用预算时会提示精简或停用。

### 主题参考文件

**主题参考文件**只登记原文／双语对照文件，每份最多 2 MiB。列表显示文件名、分段进度和原件入口，不预览正文。没有可沿用方案时才通知当前主模型，安排两个原生子代理各自完整标注同一份文件，再并行交叉复核。主模型核对未解决的实质问题、选择一份自洽方案后统一保存；不同但合理的边界无需强行合并。程序按边界取原文，不重写原件，也不自动对齐或补造双语。

同一资料库按完整文件名（含扩展名，原样精确匹配）唯一识别参考文件；不同文件应使用不同名字。同名上传更新当前主题已有登记，保留原分段逻辑，由程序按新旧文本调整边界位置；改名视为新文件。已有分段不会因为内容摘要变化自动重做，边界无法可靠对齐或某段超过 2,000 码点时，保留原件和方案并说明局部位置，处理后可再次上传。

同名文件可跨主题、跨重启沿用分段。其他主题已经采用的原件快照不因这次更新而改变。移除主题登记后，文件名基准及下一次对齐所需的原件仍保留；**清除本地数据**会一并移除。旧库存在多份同名登记时，需先保留当前主题要沿用的一份，或在其原主题更新以确定基准。

每段仍以语义为准，通常 200～600 字符，最长 2,000 字符；完整双语句对保持在同一段。整份处理需要模型容纳完整原文、定位点与结果，以及两个可用原生子代理名额。未完成时点击**重试主模型分段**，同一次宿主运行中可复用已完成的候选；重载后需重新准备未保存的候选。正式分段方案在最终提交前保留，已完成方案仅在明确要求重新分段时替换。主模型忙碌时，上传通知进入后续轮次等待处理。

全文分段完整后，已配置的嵌入服务会排队建立索引；未完成时仍可打开、读取和字面查找。支持读取 UTF-8 TXT、Markdown、CSV、TSV、JSON、JSONL、LOG 和 RST；其他格式提供原件入口，学习内容可在主聊天提炼为资产或设定。

### 译文记录与查找

**译文记录**并排展示原文和译文，可选择会话或整个主题。普通搜索框只匹配当前原文与有效最终译文正文，英文不区分大小写，提供计数、高亮和上一处／下一处定位。页面固定文案、旧版和未定稿候选不参与；查找未完成会明确提示，不触发模型调用或自动定稿。图片、表格等可通过原件链接关联，链接本身不代表已解析或翻译。

TXT、Markdown 文件的当前原文行提供**嵌入原文**；翻译会话原文行中，入口位于**重译**右侧，小字末尾显示嵌入状态。一次操作只处理该单元的一个原文文件。主模型空闲时接收任务，阅读完整原文并标记语义段与排除内容，程序仅嵌入保留正文。两处入口共享进度，可继续分段、重试嵌入、重新分段或移出索引。

导出元信息、需要原样保留的代码和 Markdown 结构不进入文件正文嵌入，标题、列表、表格及链接中的自然语言仍可保留。完整原稿和译文保持不变，排除内容以及未选择嵌入的文件仍可精确查找。主模型可先用精确查找定位译文或代码片段，再读取同一记录的实际原文核对；原译文没有自动逐句对应关系。

## 修订定稿与导出

润色已有译文时，在主聊天指出单元或版本并说明要求，例如“把单元 5 改得更自然，保留人物克制的语气和已约定的术语”。审阅新版本后，可继续给出具体意见。单次措辞修改不会自动变成长久规则；需要用于后续材料时，可要求更新对应记忆。

- **重译**追加版本，保留原稿和旧译文；短文本**编辑**追加人工版本。文件修改通过主聊天提出，外部编辑文件不会自动写回插件。
- 完整翻译自动建立最终选择，后续机器修订及人工保存会立即推进已有的“自动最终”；**设为最终**或**保存并定稿**固定人工选择，新版本不会自动替换它。不完整或取消的输出不自动定稿。
- 同一文件的查找、导出及语义检索后按需读取译文共用有效定稿；文件只对选中的原文正文建立语义向量，切换最终译文不重新嵌入原文。不同原稿的译文不会混用，旧版本默认不进入检索。
- 右键会话选择**导出译文 TXT**或**导出对照 JSON**，再选择当前会话或主题；记录页也提供导出。缺少定稿时会提示，可明确选择部分导出。主题档案另有 JSON／Markdown 导出。

导出不包含完整项目备份，也不提供导入恢复。发起下载后，请自行确认文件已保存。

## 保存存储与清理

在 **DSH 设置 → 翻译** 配置新会话默认模式、目标语言、要求和单次上限。有效设置即时保存；恢复默认不会清除历史或改写已有会话。

### 嵌入服务与语义索引

**嵌入 API**接受兼容 OpenAI Embeddings 的完整 HTTP(S) 地址（包含 `/embeddings` 路径）、模型名称和可选密钥。配置及密钥由宿主凭据服务保存，页面不回显密钥；更换服务主机需重新填写密钥。连接测试仅发送固定短文本，显示维度和耗时。

选择**建立索引**或从记忆资产页进入**语义索引**，可建立、补齐或重建。索引包含有效实体、事实、关系、分段完整的参考全文、普通短文本的当前原文与有效定稿，以及手动选择并完成分段的文件原文正文；术语与启用设定直接读取。全库建立索引不会代替用户选择文件。主模型检索限定当前主题的可访问内容，历史记录限于已打开会话，命中后可准确回读和选择上下文。未建立索引或接口失败时仍可词面查找；文件中不参与语义检索的内容通过完整记录精确查找读取。

记忆资产页显示所选主题的索引覆盖和文件状态，设置页显示全库汇总；未完成分段与读取失败分别计数，没有有效定稿的单元不计入译例或读取失败。

建立索引会将相应正文发送给配置的嵌入服务。翻译记录的文件原文发生变化后须由用户重新选择并分段；主题参考文件同名更新则沿用可对齐的分段，并按新正文更新索引。只修改或切换最终译文可复用原文向量。其他已启用索引随有效内容变化更新。修改服务地址或模型需重建，完整分段计划可继续使用。运行期向量保留在内存，已保存内容的向量由宿主保存，删除内容同步清理索引。

### 自动保存与清理

主模型会保留当前及最近一次成功翻译回合的正文。较早且已保存的成功译文在引用更短时，可改为历史版本引用，减少长聊天中重复携带的正文；用户消息和已有更正继续保留。需要讨论旧内容时，主模型可从当前主聊天已打开的翻译会话按准确原文及译文版本分页读取，原文纠错和定稿改选不改变旧引用所指内容。关闭会话后需重新打开，删除的版本不会因引用恢复。

会话历史与记忆资产统一自动保存，以宿主确认的状态为准；通过删除版本、单元、会话、主题或清空插件数据管理保留内容。模型偏好及嵌入配置独立保存。DSH 主聊天、模型调用记录和附件由 DSH 单独管理。旧配置中关闭历史保存的状态也统一转为自动保存。

启动先读取会话目录，打开、查阅或导出时按需加载正文；保存传输变化记录，失败时保留当前编辑并可重试或重新读取。删除最初创建资料的主聊天，不会删除已保存的翻译资料。

普通翻译记录结果后，主模型继续审阅和交付，程序在后台保存历史。若当前会话历史保存失败，工作区显示错误，可点击**重试保存**写入已有内容；此操作不重新翻译或新增版本。保存冲突仍需读取最新副本或明确选择覆盖。正常翻译不需要为确认保存重复调用工具，也无需另存一个文件。

| 清理层级 | 作用                                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 旧版本   | 删除可清理的旧原稿或译文正文及其独占资源，保留版本号与调用事实。最终／最新结果、保留修订的基础及未结算任务受保护。                  |
| 单元     | 清除单元的各版正文、从属记录和资源引用，保留编号与调用统计。                                                                        |
| 会话     | 删除会话内容及从属资源，默认保留主题记忆。                                                                                          |
| 主题     | 删除主题、会话、主题资产及参考登记，保留用户级设定和其他主题使用的共享文件。                                                        |
| 插件     | **本地数据**标题右侧的**清除本地数据**需二次确认，移除插件资料、设置、索引及专属嵌入凭据；保留用户原文件和 DSH 主聊天。 |

清理需确认，内容先失效，再释放独占文件；共享原件按实际使用保留。**存储与空间**可查看占用、删除无法读取的历史副本及清理孤立记录；标题行右侧提供**回收未引用原稿**与**刷新统计**。文件删除失败时正文不会恢复，残留可在重启后继续回收；文档还可清理未采用翻译块。

相关任务运行中或结果未知时先核对。已导出的文件、用户原件及已发送给主模型的内容不会随本地删除撤回。

## 发行包与源码更新

### 发行包更新

安装包入口：[翻译插件 Releases](https://github.com/Mulibaixi/dsh-translation-plugin/releases) · [Composer Releases](https://github.com/Mulibaixi/dsh-composer-extension/releases)。选择 `.tgz` 附件，按对应发行说明核对配套版本；当前翻译工作流配套 Composer `0.4.6`。

使用 DSH CLI 时，以下命令固定安装翻译插件 `0.26.11` 与 Composer `0.4.6`，先安装 Composer。需要其他版本时，从对应 Release 复制 `.tgz` 附件链接替换；新功能随对应版本的发行包提供。

```powershell
dsh plugin --profile desktop add https://github.com/Mulibaixi/dsh-composer-extension/releases/download/v0.4.6/dsh-composer-extension-0.4.6.tgz
dsh plugin --profile desktop add https://github.com/Mulibaixi/dsh-translation-plugin/releases/download/v0.26.11/dsh-translation-plugin-0.26.11.tgz
```

上述命令使用桌面 `desktop` profile；Web 环境使用自身实际 profile，联动组件支持范围仍以 Composer 说明为准。使用桌面插件管理器安装时无需另装 CLI。

1. 等待正在执行的任务结束，确认历史与记忆已经保存；需要保留完整回退点时，按下节备份。
2. 下载带版本号的新 `.tgz`，在 DSH 插件管理器的安装输入框填写其完整路径或版本下载链接，安装并启用。**不需要先卸载旧版**；使用新的文件名或链接，不要只覆盖原路径中的同名包。
3. 只更新本次发行说明要求更新的插件。两包需要配套更新时，先安装 Composer，再安装翻译插件。
4. 按管理器提示刷新、重载或重启。宿主支持时，翻译插件与 Composer 扩展代码都可以重载；不能即时载入时，以管理器的重启提示为准。
5. 更新 Composer 后打开“Composer：联动组件维护”。已就绪表示可以继续使用现有组件；只有显示补丁已准备、等待退出安装时，才正常完全退出并重开 DSH 来应用补丁。

插件包更新、宿主补丁替换与资料库迁移分别判断。补丁内容没有变化且已安装匹配时，不会因为 Composer 版本号变化重复安装补丁。若 DSH 自身升级改变了相关模块，则按维护状态重新检测，不手动覆盖 `app.asar`。

如果管理器提示“已安装”，先确认填写的是新版本包的路径或版本链接，而不是插件包名或同一旧路径。若当前管理器明确要求卸载再安装，可在同一次 DSH 运行中完成重装并启用；Composer 会在重新启用时取消检测到的待执行自动恢复。日常升级不需要重走“卸载 → 退出恢复原包 → 重装 → 再退出安装补丁”的卸载验收循环。

### 源码更新

更新原来安装的源码目录，按锁文件安装依赖并重新构建，再通过 DSH 刷新或重载。需要同时构建两包时，先 Composer、后翻译插件。源码目录安装与 `.tgz` 安装是两种方式，发行包用户无需安装 Node.js、pnpm 或执行构建。

源码更新同样不要求先卸载；补丁是否需要完整退出，仍看 Composer 的维护状态。

## 资料库备份与恢复

当前没有插件内的完整资料库备份／导入入口。TXT、Markdown、JSON 等导出用于交付和查阅，不能直接导入还原整个资料库。以下是 **Windows 桌面版、同一台电脑和同一 Windows 用户**下的完整数据快照与回退方法，不是跨设备迁移工具。

### 备份完整数据快照

1. 等待任务结束并确认保存，正常完全退出 DSH，包括托盘进程。
2. 建立一个带日期的备份目录，例如 `DSH-backup-20261030`，同时保留对应的 DSH 版本号和两个插件版本号／分发包；源码安装则保留当时的源码提交及构建版本。
3. 在资源管理器中复制下面两个**完整目录**到备份目录，分别命名为 `dsh-home` 和 `desktop-user-data`。若自定义了数据目录，使用实际路径。

| 默认 Windows 位置                           | 备份名称              | 保存范围                                                                              |
| ------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------- |
| `%USERPROFILE%\.dsh`，或实际 `DSH_HOME` | `dsh-home`          | 宿主保存的翻译历史、记忆、原稿／参考副本，以及 DSH 会话、profile 配置与插件安装数据。 |
| `%APPDATA%\@deepseek-ai\dsh-desktop`      | `desktop-user-data` | 桌面浏览器存储、资料库命名空间、界面设置等。                                          |

4. 另行保留数据目录外的原稿、参考资料及 Markdown 引用的图片目录，保留原路径和相对目录结构。

两个目录应来自同一次完全退出后的快照。只复制 `assets.sqlite` 或只导出译文不构成完整备份；资料库身份还与桌面浏览器本地存储关联。此方案包含整个 DSH 数据环境，恢复时也会回退 DSH 主聊天、配置和插件安装状态。

### 从快照恢复

1. 准备备份对应的 DSH 与插件版本，使用同一 Windows 用户，完全退出 DSH。
2. 将当前的两个数据目录分别重命名保留，例如加上 `.before-restore-日期`，作为本次恢复前的回退副本。
3. 将备份中的 `dsh-home` 完整复制回原 `DSH_HOME` 位置（默认目录名为 `.dsh`），将 `desktop-user-data` 完整复制回原 `dsh-desktop` 位置，不与现有目录混合。
4. 将外部原稿和图片等恢复到原路径及对应相对目录，再启动 DSH，核对原主题、会话、历史版本和记忆。先确认备份对应版本可用，再按上一节执行后续升级。

资料快照不包含 DSH 应用安装目录和 `app.asar`。Composer 的补丁备份／恢复与资料库恢复是两件事，宿主补丁按 Composer 的“联动组件维护”说明处理。

## 已有资料的升级与迁移

升级已有资料时注意：

- 会话历史与记忆资产统一自动保存，旧配置中的关闭状态不再生效。
- 旧浏览器测试历史不自动导入，重要内容应先导出；旧文件／文档任务需从当前文件输入重新发送原稿才能翻译。
- 参考文件统一在“其他记忆”登记原文／双语对照文件；已有全文须完成主模型分段后建立语义索引。旧片段登记工具和依据依赖机制已移除，已有记录加载时会清除旧登记字段。
- 文件译文记录的旧固定切片与译文向量不再用于语义检索；记录仍完整保留，TXT、Markdown 原文需通过文件行“嵌入原文”手动选择后建立新索引。
- 新版保存的数据可能无法由旧版读取，不要让新旧版本同时使用同一份资料。导出文件目前不能导入恢复，不能替代完整数据备份。
- 文件名分段基准使用 v8 本地数据库格式；不支持该格式的旧版插件无法直接读取，降级时需恢复对应版本的完整备份。

禁用或卸载插件不会自动删除本地资料。版本变化见 [CHANGELOG](../CHANGELOG.md)。

## 运行诊断与问题反馈

普通文本机器版本提供**导出调用日志**，记录该版本的提示、输入、输出与执行事件。日志含翻译正文，按会话和版本校验，仅在原宿主运行期间可用；需要保留时先导出，分享前检查敏感内容。

在 DSH 宿主日志搜索 `[dsh-translation]`，按 `traceId` 关联操作；客户端保存或依据检查失败也会在浏览器控制台输出摘要。

| 阶段                                   | 说明                                       |
| -------------------------------------- | ------------------------------------------ |
| `model.prepare`／`model.stream`    | 模型准备、输出长度、完成／取消及失败阶段。 |
| `embedding.request`                  | 输入数量、HTTP 状态、返回维度和接口错误。  |
| `memory.index`／`memory.search`    | 覆盖、词面／向量命中及降级情况。           |
| `history.write`／`history.cleanup` | 保存状态、删除、共享保留及残留清理。       |

摘要记录状态、耗时、错误码和堆栈位置，不包含正文、提示词、查询、接口地址或密钥。DSH 的模型会话记录另行管理，可能包含请求正文。接口连通、索引完成或日志显示成功，都不能单独证明译文与召回质量。

反馈时提供 DSH／插件版本、复现时间、操作、预期与实际现象，以及关联摘要。质量问题还需指出具体段落和判断依据。
